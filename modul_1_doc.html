3. Penjelasan Koding Baris per Baris

A. Struktur Data Tile (server/pkg/engine/tile.go)

type Tile struct {
    ID      int  `json:"id"`       // ID unik 0-143 untuk setiap keping fisik
    Suit    Suit `json:"suit"`     // Bamboo, Dot, Character, Wind, Dragon, Flower, Season
    Value   int  `json:"value"`    // Angka 1-9 atau ID simbol angin/naga
    IsBonus bool `json:"is_bonus"`// True jika Flower atau Season
}

Mengapa Perlu Field ID Unik?
Meskipun dalam permainan Mahjong ada 4 keping "5-Bamboo" yang tampak identik, di server setiap keping memiliki ID unik (misal ID 16, 17, 18, 19). Hal ini penting untuk melacak riwayat pergerakan fisik setiap batu dari wall ke tangan, discard pond, atau meld terbuka tanpa resiko bug duplikasi.

// Mengacak urutan array dengan Fisher-Yates
for i := len(shuffled) - 1; i > 0; i-- {
    j := rng.Intn(i + 1)
    shuffled[i], shuffled[j] = shuffled[j], shuffled[i]
}

Kenapa Tidak Menggunakan Random Biasa?
Fungsi math/rand biasa menggunakan seed waktu (timestamp) yang bisa diprediksi oleh hacker. Dengan mengambil sumber entropi dari crypto/rand, urutan kartu menjadi 100% acak, adil, dan mustahil dimanipulasi dari sisi client/pemain.

C. Pointer Pengambilan Tile (Head vs Tail)

// Draw normal mengambil dari depan (Head)
func (w *Wall) DrawTile() (Tile, error) {
    tile := w.Tiles[w.HeadIndex]
    w.HeadIndex++  // Geser penunjuk ke kanan
    return tile, nil
}

// Replacement Draw (Flower / Kong) mengambil dari belakang (Tail)
func (w *Wall) DrawReplacementTile() (Tile, error) {
    tile := w.Tiles[w.TailIndex]
    w.TailIndex--  // Geser penunjuk ke kiri
    return tile, nil
}
💡 Insight Teknis untuk Pemula:
Teknik menggunakan HeadIndex dan TailIndex ini disebut Pointer Array. Keunggulannya adalah sangat hemat memori (RAM) dan tidak memerlukan penghapusan elemen array (*slice reallocation*), sehingga eksekusi draw berlangsung secepat kilat (0 nanodetik).
